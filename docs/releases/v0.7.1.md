# R-TrustTunnel 0.7.1

[Русский](#русский) · [English](#english) · [Технические детали / Technical details](#technical-details)

## Русский

### Коротко

0.7.1 не добавляет новый протокол. Приложение умеет само проверить, вышла ли
новая версия, и скачать файл для вашей платформы — ставить его всё равно
придётся вам. В режиме «весь компьютер» можно запретить IPv6, даже если сервер
его умеет. Уже сохранённый конфиг портала подключается без живого портала.
Журнал больше не забивается отладкой, а медленное рукопожатие не обрывается
через четыре секунды.

### Что нового

**Проверка обновлений на GitHub.** В Native, WebView, терминальном клиенте и
на Android можно посмотреть последний стабильный релиз. Если он новее,
приложение скачает установочный файл именно этой платформы и сверит его со
списком `SHA256SUMS` из того же релиза. Само оно ничего не устанавливает и не
запускает. Совпадение хеша значит только то, что файл совпал со списком: это
не подпись издателя и не замена подписанного канала обновлений Windows.
На iOS кнопки скачивания нет — открывается только страница релиза, потому что
установочного файла iOS по-прежнему нет.

**Можно запретить IPv6.** В режиме «весь компьютер» появился переключатель
«Полностью блокировать IPv6» (Native и WebView). IPv6 перехватывается и
отклоняется на этом компьютере: ни в туннель, ни мимо него. Приложения
переходят на IPv4. Настройка сохраняется и переживает переподключение и
Always-on. Старая служба, которая этого не умеет, не проигнорирует переключатель
молча: подключение не начнётся, пока службу не обновят вместе с окном.

**Портал не нужен, чтобы подключиться к уже сохранённому конфигу.** Если
конфиг уже на диске, Native, WebView, терминальный клиент и Android
подключаются без живого портала. iOS так и работал. Ещё действующий токен
продлевается сам, не чаще раза в сутки, в том числе при включённом VPN.
Просроченный токен больше не отправляется; если портал ответил 401 или 403,
тот же токен повторно не уходит.

Android TV в этот релиз не входит. Для телевизора по-прежнему отдельный
предварительный пакет
[v0.7.1-tv.3](https://github.com/onixus/Rust-trustvpn/releases/tag/v0.7.1-tv.3).
Телефонный APK 0.7.1 его не заменяет и на него не ставится: это разные
приложения.

### Что исправлено

**Linux Flatpak снова показывает маршрут и связь.** В опубликованном 0.7.0
строки «Маршрут» и «Связь» оставались «нет данных»: внутри Flatpak нет команды
`ip`, и проверка до неё не доходила. Теперь маршрут спрашивается у ядра
напрямую. На установленном Flatpak 0.7.0 с этим исправлением, в режиме «весь
компьютер» на Fedora 43, все пять проверок прошли. Повтор на пакете, собранном
из этого тега, ещё не делался.

**Медленное рукопожатие больше не считается обрывом.** Четыре секунды на адрес
обрывали живой путь HTTP/3 раньше, чем он успевал повторить пакет. Теперь на
адрес даётся 10 секунд и TCP, и QUIC. Общий предел сессии (20 секунд) и
попытки (30 секунд) не выросли.

**На Windows видно, почему остановился туннель.** Служба пишет ту же строку
остановки транспорта, что и на macOS. Обычное «Отключить» и остановка службы
из Windows в журнал как авария не попадают.

**Журнал хранит важное дольше, а отладку — короче.** Отладочные строки живут
15 минут, предупреждения — 30, ошибки — час, критичные — сутки. Ошибки
подключения считаются ошибками. Строки, записанные до появления уровней,
по-прежнему хранятся до семи дней. Потолок 15 МБ не изменился. Последние десять
эпизодов переподключения не исчезают через час: иначе после успешного
восстановления не остаётся, почему связь рвалась.

**Меньше лишней работы в простое.** Служба Windows и Android VPN в простое
больше не опрашивают стек каждые 5 мс. Живые соединения по-прежнему
обслуживаются в те же 5 мс. На Windows индекс адаптера читается один раз, до
смены маршрутов и DNS.

### Как обновиться

- **macOS:** закройте R-TrustTunnel, скачайте
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` и установите **один** из пакетов
  внутри: Native, WebView или Both.
- **Android (телефон):** ставьте поверх 0.7.0 и 0.6.x — профили сохранятся.
  Версии 0.5.x и старше сначала удалите (локальные профили при этом удалятся —
  заранее экспортируйте их). Не ставьте телефонный APK вместо пакета Android TV
  и наоборот.
- **Windows / Linux:** окно приложения и служба VPN должны быть из одного
  релиза — обновляйте их вместе. На Linux обновите и пакет `rtrust-host` этой
  же версии.
- Хранилище с профилем VLESS по-прежнему не читается версиями 0.6.x. После
  добавления такого профиля не откатывайтесь на 0.6.x, в том числе откатом
  обновления desktop.

Подписанный канал Windows в этих исходниках — sequence 14. Появление файлов на
GitHub само не включает автообновление: продвижение `latest` по-прежнему
отдельный шаг после проверки.

### Что пока стоит знать

- Пакеты для macOS не подписаны Apple Developer ID; при первом запуске может
  понадобиться разрешить запуск в «Системных настройках → Конфиденциальность и
  безопасность». Установщик Windows не подписан, SmartScreen может предупредить.
- Это всё ещё предварительная версия. Проверка на установленных пакетах,
  собранных из этого тега, не проводилась (см. таблицу ниже).
- Проверка GitHub не доказывает подпись издателя. Скачанный файл нужно ставить
  самому.
- Идентичность пакета Android TV не менялась. Не публикуйте TV-сборку из этого
  тега под старым именем `0.7.1-tv.3`.

## English

### In short

0.7.1 does not add a protocol. The app can check whether a newer version is
out and download the file for your platform; you still install it yourself.
Whole-computer mode can refuse IPv6 even when the server can carry it. A portal
config that is already saved connects without a live portal. The journal no
longer fills up with debug lines, and a slow handshake is no longer cut off
after four seconds.

### What's new

- **A GitHub update check.** Native, WebView, the terminal client and Android
  can look up the latest stable release. When it is newer, the app downloads
  this platform's package and checks it against that release's `SHA256SUMS`.
  It never installs or runs the file. A matching hash only means the bytes
  match the list: it is not a publisher signature and it does not replace the
  signed Windows update channel. iOS only opens the release page, because no
  installable iOS file is published.
- **IPv6 can be blocked.** Whole-computer mode has a "Block IPv6 completely"
  switch in Native and WebView. IPv6 is captured and refused on this computer:
  neither through the tunnel nor around it. Apps fall back to IPv4. The setting
  is saved and kept across reconnect and Always-on. An older service that
  cannot do this does not ignore the switch: the connection does not start
  until the service is updated with the window.
- **A saved portal config connects without the portal.** Native, WebView, the
  terminal client and Android connect from a config already on disk. iOS
  already did. A token that is still valid renews itself, at most once a day,
  including while the VPN is on. An expired token is not sent; after a 401 or
  403 the same token is not sent again.

Android TV is not part of this release. TVs keep the separate pre-release
[v0.7.1-tv.3](https://github.com/onixus/Rust-trustvpn/releases/tag/v0.7.1-tv.3).
The phone APK does not replace it and does not install over it: they are
different apps.

### What's fixed

- **Linux Flatpak shows Route and Connectivity again.** In the published 0.7.0
  those rows stayed "no data": the Flatpak has no `ip` command, so the check
  never reached the connection step. The route is now asked of the kernel
  directly. On an installed 0.7.0 Flatpak with this fix, in whole-computer mode
  on Fedora 43, all five checks passed. That has not been repeated on a package
  built from this tag.
- **A slow handshake is no longer a timeout.** Four seconds per address cut off
  a live HTTP/3 path before it could retransmit. TCP and QUIC now share 10
  seconds per address. The 20-second session limit and the 30-second attempt
  limit are unchanged.
- **Windows records why the tunnel stopped.** The service writes the same
  transport-stop line as macOS. Stop and a Windows service shutdown are still
  not recorded as a failure.
- **The journal keeps what matters.** Debug lines last 15 minutes, warnings 30,
  errors one hour and critical lines one day. Connection failures are errors.
  Lines written before levels existed still last up to seven days. The 15 MB
  cap is unchanged. The ten newest reconnect episodes are kept past the
  one-hour error window, so a tunnel that has already recovered still has a
  record of why it dropped.
- **Less idle work.** An idle Windows service and the Android VPN no longer
  poll the stack every 5 ms. Live flows still poll within 5 ms. On Windows the
  adapter index is read once, before routes or DNS change.

### How to update

- **macOS:** quit R-TrustTunnel, download
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` and install **one** package inside:
  Native, WebView or Both.
- **Android (phone):** install over 0.7.0 and 0.6.x; profiles stay. Uninstall
  0.5.x and older first, which removes local profiles — export them first. Do
  not install the phone APK in place of the Android TV package, or the other
  way around.
- **Windows / Linux:** the app window and the VPN service must come from the
  same release. On Linux, update the `rtrust-host` package of this release too.
- A vault with a VLESS profile still cannot be read by 0.6.x. Do not roll back
  to 0.6.x after adding one, including a desktop update rollback.

The signed Windows channel in these sources is sequence 14. Files on GitHub do
not turn auto-update on by themselves: promoting `latest` is still a separate
step after validation.

### What to know

- macOS packages are not signed with an Apple Developer ID, and the Windows
  installer is not Authenticode signed; your OS may ask you to confirm the
  launch.
- This is still a preview. Installed packages built from this tag have not been
  checked (see below).
- The GitHub check does not prove a publisher signature. You install the
  downloaded file yourself.
- The Android TV package identity is unchanged. Do not publish a TV build from
  this tag under the old name `0.7.1-tv.3`.

## Technical details

Prepared from `origin/main` `3d2a94a` (merge of #133). The tag is not cut and
the packages are not published by this record. Published Latest remains
[v0.7.0](v0.7.0.md) until this tag is published. Android TV stays the separate
pre-release `v0.7.1-tv.3`; its application id, versionName and versionCode are
not bumped here.

Workspace **0.7.1**, desktop update **sequence 14**, phone Android versionName
`0.7.1` / versionCode **70005**, iOS 0.7.1 (70005). TV defaults stay
`0.7.1-tv.3` / 70004 and must not be republished from this tag under that name.
Desktop control IPC stays **v7**; GUI and service must still come from the same
package. macOS publishes only the UI Choices DMG
([release assets](README.md)). Previous desktop/phone release:
[v0.7.0](v0.7.0.md).

### Since v0.7.0

- **GitHub release check** (#131): Native, WebView, TUI and Android look up the
  latest stable release of `onixus/Rust-trustvpn` and download the asset named
  for this platform in that release's unsigned `SHA256SUMS`. Nothing is
  installed or executed. iOS opens the release page only. The Ed25519 channel
  is unchanged. See [secure updates](../secure-updates.md).
- **Optional whole-computer IPv6 block** (#129): saved, sent only to a service
  that advertises the capability, kept across reconnect and Always-on. An older
  service fails the connect instead of ignoring the flag. The profile is not
  described as relaying IPv6 while the block is on.
- **Saved portal config** (#127): connect without a live portal; a still-valid
  token renews at most once a day; an expired token is not sent, and a 401/403
  is remembered so the same token is not sent again.
- **Journal** (#124, #128): level windows (debug 15 min, warning 30 min, error
  60 min, critical 24 h); pre-level lines keep the seven-day bound; 15 MB cap
  unchanged; the ten newest `keep=reconnect` lines outlive the error window.
  See [diagnostics journal](../diagnostics-journal.md).
- **Handshake and Windows stop line** (#125): 10 s per-address budget for TCP
  and QUIC; 20 s session and 30 s attempt limits unchanged. Windows journals
  the transport-stop line; Stop and SCM shutdown do not.
- **Linux Flatpak route check** (#121): one `RTM_GETROUTE` on `NETLINK_ROUTE`
  instead of `/usr/sbin/ip`. Reported PASS on an installed 0.7.0 Flatpak plus
  this fix, Fedora 43 KDE, full tunnel. Not repeated on `3d2a94a`.
- **Idle dataplane** (#122): idle Windows service and Android VpnService no
  longer poll the TCP stack every 5 ms; live flows still do. The Wintun index
  is read once before routes or DNS change.
- Docs only (#119, #120, #133): #113 acceptance wording, 0.7.0 screenshots and
  README structure, project status after v0.7.0. Not a new package acceptance.
- Not in this desktop/phone release: open PR #126 (Rttun adapter; Wintun remains
  the documented Windows adapter).
