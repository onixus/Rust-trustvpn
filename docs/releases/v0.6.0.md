# v0.6.0 — observations, diagnostics and guarded recovery (pre-release candidate)

**Status: preview candidate, not published, not production-ready.** Workspace
version 0.6.0, desktop update **sequence 10**, Android versionName
`0.6.0-preview.2` / versionCode 60002, iOS 0.6.0 (60002); the tag itself declared
`0.6.0-preview.1` / 60001. This document describes
the source candidate. No artifact has been built, signed or published for it,
and no update channel `latest` is promoted. Promotion of `latest` on any
platform requires a completed exact-package acceptance matrix
([package-acceptance.md](../package-acceptance.md)) and a separate decision.

Previous public desktop build: [v0.5.0-rebuild.9](v0.5.0.md) (sequence 9);
previous mobile artifacts: v0.5.0.

## What changed since v0.5.0-rebuild.9

Merged pull requests #29, #37–#41 and #43–#60 (#42, the macOS widget, is still
open and not part of this candidate).

### Shared core and all clients

- Typed VPN observations (passed/failed/configured/unknown/stale/unsupported)
  with source, freshness and generations; Connected no longer implies verified
  DNS, routes, guard or reachability (#37).
- Route explanations from the same evaluator the dataplane uses, offline route
  preview, and a CNAME/address TTL provenance fix (#39).
- Apps connect the profile the user selected instead of the default; permitted
  backups are resolved relative to the actual primary (#50).
- Managed profiles keep provenance, assigned routing and finite offline
  receipts; live policy changes and diagnostics are fenced by revision (#54).
- Portal profile-limit 409 responses are explained on desktop, Android and iOS;
  other 409s still show the revision-conflict text (#60).

### Desktop (Windows, Linux, macOS)

- Split-mode DNS is routed through the VPN when the selection tunnels the
  resolver (#29).
- Control IPC is versioned with capability negotiation, now **IPC v6**
  (#37, #48, #51, #54, #59). GUI and service must come from the same package.
- OS-attested network-change and kernel-clock resume events invalidate earlier
  observations (#43).
- Bounded system-path diagnostics through the active TUN/full connection, typed
  verdicts, endpoint probe and follow-up actions; automatic background checks
  every 30 seconds (#40, #45, #53). Windows gains resolver, live-adapter route
  and interface-bound HTTPS checks; Linux gains a service-owned endpoint check
  (#48).
- Opt-in ordinary-session recovery through up to three user-approved backup
  profiles; the guard is never lifted during recovery (#46).
- Opt-in Always-on recovery through encrypted ordered backup candidates on
  **Linux and Windows only**; bounded jittered reconnect budgets that switching
  candidates cannot replenish (#47, #49).
- macOS: VPN restore after sleep with bounded retries and responsive IPC (#51);
  the service keeps supervising the VPN when GUI IPC closes (#56); Recover of a
  live session requires the session owner token (#59).
- Windows: selected profile/shortcut icon fixes (#50); the acceptance runner no
  longer toggles the physical adapter unless explicitly requested (#52); the
  service admits the previous IPC version for `Capabilities` and `PrepareUpdate`
  only, for the previous updater's rollback reservation (#60).

### Android

- Compact resizable widget and Quick Settings tile (#41); widget button colour
  follows VPN state (#44).
- Native network/link and deep-sleep events invalidate observations; mobile
  flow-policy capture (#47, #48).
- Managed recovery with an explicit primary and compatible backups and an owned
  blocking TUN while managed access is unavailable (#54).
- Managed profile batches that change during sync are rejected (#58).
- The published APK is `0.6.0-preview.2` / 60002, built after the tag from the
  merge of #63: the VPN follows the current network after a handoff, prefers
  the network Android prefers, recovers an Always-on session switched on in
  Settings, an optional "VPN data usage" setting, and one check per status
  line. It is signed with a **new key** (certificate SHA-256
  `4aa431cd89387e969da006b0a76288ac725fa17e952a83641df80d4b977306af`) and
  cannot update installations from v0.5.0 or earlier.

### iOS

- Provider path/wake events feed the shared invalidation adapter (#47).
- Managed profile batch fence (#58) and 409 limit texts (#60).

### Release engineering

- Go fixture HTTP/2 CVE patch and toolchain-keyed fixture cache (#38).
- Signed publication verifies the pinned-root envelope, exact sequence/target/URL,
  size and SHA-256 before any SSH; acceptance binds to the signed envelope hash
  (#49).
- Release builds and signing are bound to an exact source commit and tree (#57);
  signing now also runs the signing tool with `--locked`.
- The Windows service admits `PrepareUpdate` from the published sequence-9
  updater (IPC v1) so automatic rollback 10 → 9 can reserve it (this release).

## Compatibility

- **Update metadata:** the compiled updater identifies as sequence 10 and
  release signing accepts only a sequence-10 manifest for this source.
  `CURRENT_IPC` (signed package transaction field) remains **1**, so a sequence-9
  updater accepts a 1..1 package. The rollback envelope for an installed 0.6.0
  is fetched from the versioned sequence-10 path, which must be published
  together with the candidate.
- **GUI/service IPC v6:** strict on Linux and macOS. A v5 or older GUI cannot
  control a v6 service; install GUI and service together.
- **Windows rollback 10 → 9.** The installed sequence-9 updater from
  v0.5.0-rebuild.9 speaks control IPC **v1**, which the #60 `VERSION - 1`
  exception (v5) does not cover. The service now also admits the published
  updater versions in `RELEASED_UPDATER_VERSIONS` (`[1]`) for `PrepareUpdate`
  only and answers in the v1 reply shape, so the old updater can reserve the
  upgraded service and reinstall sequence 9 after a failed health check. All
  other v1 commands are refused; authentication and the guard/active-session
  refusal are unchanged. Unit tests pin the wire shapes, and
  a lab-signed rehearsal passed on the Windows lab on 2026-10-13: the published
  sequence-9 package and its updater (IPC v1) installed the 0.6.0 candidate
  Setup built from exact source `974debf` (Rust and Windows code identical to
  the final candidate), an injected health failure made the v1 updater reserve
  the v6 service and roll back to sequence 9, and the retry to 10 succeeded; the
  encrypted vault stayed byte-identical and owned routes/WFP were unchanged.
  The manifests were signed with a throwaway lab key (the runner had a lab
  `root.pub`), so the production-key signature of sequence 10 and Authenticode
  remain NOT RUN, and Windows `latest` must not move to sequence 10 before the
  genuinely signed sequence-10 metadata exists and the acceptance matrix passes.
- **Server:** portal 409 detail strings and profile limits are server contracts
  owned by onixus/tunnel; this candidate does not change server behaviour.

## Preview limitations

- macOS packages are only ad-hoc sealed: no Developer ID signature and no
  notarization. macOS `latest` remains withheld.
- Windows packages are not Authenticode signed; only the update metadata is
  signed.
- No dependency audit (`cargo audit`/`cargo deny`) is configured. Dependency
  vulnerabilities are covered only by the Trivy filesystem scan in Jenkins.
- No runner currently performs an independent packet capture on the physical
  interface. Absence of DNS/IPv6/direct-traffic leaks is supported only by
  active probes and attribution in containers or the emulator, not by an
  independent capture of an installed package.
- Always-on recovery through backup profiles is supported on Linux and Windows
  only; macOS and mobile are unsupported.
- iOS device archives require Apple signing and are not an installable IPA.
- Route groups remain desktop-only.
- Recovery and resource budgets and the ≥24 h soak duration are not yet
  approved, so no soak or budget result exists.
