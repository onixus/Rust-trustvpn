# R-TrustTunnel 0.7.0

[Русский](#русский) · [English](#english) · [Технические детали / Technical details](#technical-details)

## Русский

### Коротко

0.7.0 добавляет четвёртый протокол — VLESS через CDN — и журнал неудачных
подключений, который переживает перезагрузку. Кроме того, на Windows строки
«Защита» и «DNS» больше не показывают ложную ошибку, а управляемые профили
на macOS снова подключаются в режиме «весь компьютер».

### Что нового

**VLESS через CDN (предварительная версия).** Ссылку `vless://` из CDN-панели
сервера можно вставить или импортировать из файла, как обычный профиль.
Подключение идёт через WebSocket и TLS, внешняя программа Xray не нужна.
Поддерживаются TCP и UDP. Ограничения:

- транспорт XHTTP импортируется, но подключение с ним пока не работает;
- отпечаток браузера (`fp=chrome`) не эмулируется, это видно в карточке профиля;
- при включённой защите «весь компьютер» на macOS и Windows другие сайты,
  которые стоят за теми же адресами CDN, недоступны;
- если UUID отозван, статус может показывать «подключено», хотя сайты не
  открываются; приложение заметит это по серии пустых соединений;
- версии до 0.7.0 не могут прочитать хранилище, в котором есть профиль VLESS:
  после добавления такого профиля не откатывайтесь на 0.6.x.

**Журнал неудачных подключений.** Службы VPN на macOS, Linux и Windows и
автоматическое восстановление SOCKS теперь записывают, почему не удалось
подключиться или переподключиться: класс ошибки, транспорт, попытку и
длительность. В журнал не попадают адреса серверов, ключи, имена профилей и
тексты ошибок сервера. Он хранится не дольше семи дней и не больше 15 МБ и
остаётся после перезагрузки. На macOS журнал службы переехал в
`/Library/Logs/R-TrustTunnel/events.log`.

**Понятно, почему оборвалось соединение.** На macOS в журнале службы теперь
видно, кто закрыл транспорт (сервер, сеть или сам клиент) и на каком шаге не
удалось переподключиться.

### Что исправлено

**Windows: «Защита» и «DNS» больше не красные зря.** В режиме «весь компьютер»
эти строки показывали «ошибка», хотя защита работала. Теперь приложение
проверяет, что пробный пакет остановило именно его правило, и показывает
«пройдено». Если доказать это нельзя, строка остаётся «неизвестно», а не
зелёной.

**macOS: управляемые профили снова подключаются.** Профили, выданные порталом
с ограниченным сроком доступа, в режиме «весь компьютер» отклонялись с ошибкой
`Service freshness capability required`. Теперь служба сама следит за сроком
доступа, в том числе во время сна и без открытого окна приложения.

### Как обновиться

- **macOS:** закройте R-TrustTunnel, скачайте
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` и установите **один** из пакетов
  внутри: Native, WebView или Both.
- **Android:** устанавливайте поверх 0.6.x — профили сохранятся. Версии 0.5.x и
  старше сначала удалите (при этом удалятся локальные профили — заранее
  экспортируйте их).
- **Windows / Linux:** окно приложения и служба VPN должны быть из одного
  релиза — обновляйте их вместе. На Linux обновите и пакет `rtrust-host`.

### Что пока стоит знать

- Пакеты для macOS не подписаны Apple Developer ID; при первом запуске может
  понадобиться разрешить запуск в «Системных настройках → Конфиденциальность и
  безопасность». Установщик Windows не подписан, SmartScreen может предупредить.
- Это всё ещё предварительная версия: не все сценарии проверены на
  установленных пакетах (см. таблицу ниже). VLESS через настоящий CDN на
  установленных пакетах ещё не принят.

## English

### In short

0.7.0 adds a fourth protocol, VLESS over a CDN, and a connection failure
journal that survives a reboot. On Windows the Protection and DNS rows no
longer show a false failure, and managed profiles on macOS connect in
whole-computer mode again.

### What's new

- **VLESS over a CDN (preview).** Paste or import a `vless://` link from the
  server's CDN panel like any other profile. The client speaks WebSocket and
  TLS itself; no Xray binary is needed. TCP and UDP are supported. Limits:
  - XHTTP links import, but connecting with them is not supported yet;
  - the browser fingerprint (`fp=chrome`) is not emulated, and the profile
    details say so;
  - with whole-computer protection on macOS and Windows, other sites behind
    the same CDN addresses are unreachable;
  - with a revoked UUID the status can say "connected" while sites do not load;
    the app notices it from a run of empty connections;
  - versions before 0.7.0 cannot read a vault that contains a VLESS profile;
    do not roll back to 0.6.x after adding one.
- **Connection failure journal.** The macOS, Linux and Windows VPN services and
  automatic SOCKS recovery record why a connect or reconnect failed: error
  class, transport, attempt and duration. Server addresses, keys, profile names
  and server error texts are not recorded. The journal keeps at most seven days
  and 15 MB and survives a reboot. On macOS the service journal moved to
  `/Library/Logs/R-TrustTunnel/events.log`.
- **Why a connection dropped.** On macOS the service journal now shows who
  closed the transport (the server, the network or the client) and which
  reconnect step failed.

### What's fixed

- **Windows: no false red Protection and DNS.** In whole-computer mode these
  rows said "failed" although the guard worked. The app now checks that its own
  rule dropped the probe packet and shows "passed". When that cannot be proven,
  the row stays "unknown", never green.
- **macOS: managed profiles connect again.** Portal profiles with a limited
  access lease were refused in whole-computer mode with
  `Service freshness capability required`. The service now enforces the lease
  itself, across sleep and without an open app window.

### How to update

- **macOS:** quit R-TrustTunnel, download
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` and install **one** package from it:
  Native, WebView or Both.
- **Android:** install over 0.6.x; profiles are kept. Uninstall 0.5.x and older
  first — this deletes local profiles, so export them.
- **Windows / Linux:** the app window and the VPN service must come from the
  same release; update them together. On Linux, update `rtrust-host` as well.

### Good to know

- macOS packages are not signed with an Apple Developer ID, and the Windows
  installer is not Authenticode signed; your OS may ask you to confirm the launch.
- This is still a preview: not every scenario has been checked on installed
  packages (see below). VLESS through a real CDN has not been accepted on
  installed packages.

## Technical details

Workspace 0.7.0, desktop update **sequence 13**, Android versionName `0.7.0` /
versionCode 70001, iOS 0.7.0 (70001). Desktop control IPC stays **v7**; GUI and
service must still come from the same package. Previous release:
[v0.6.2](v0.6.2.md). macOS publishes only the UI Choices DMG
([release assets](README.md)).

### Since v0.6.2
- **VLESS over a CDN** (#112, issue #111 stays open for its follow-ups):
  `protocol: "vless"` profiles, fail-closed `vless://` import and exact
  round-trip export; engine TCP → TLS (ALPN `http/1.1`) → WebSocket (own
  RFC 6455 codec) → VLESS per flow, UDP up to 8190 bytes, no ICMP; UUID and path
  are secrets. Interop with official Xray-core v26.10.21 on loopback
  (`ci/vless_interop.py`), also in Jenkins on macOS and in `ci/linux.py`.
  See [VLESS](../vless.md).
- **Connection failure journal** (#114, issue #107): typed, bounded
  (7 days / 15,000,000 bytes) best-effort journal for the services and automatic
  SOCKS recovery; persistent paths with descriptor-relative Unix checks and
  protected Windows DACLs. The macOS service no longer writes the ephemeral
  `/private/var/run/rtrust/events.log`; old files there are not migrated or
  deleted. See [diagnostics journal](../diagnostics-journal.md).
- **Transport stop and reconnect reasons** (#113): `Close` keeps the h2 GOAWAY
  code and side, peer EOF, socket error kind, TLS and QUIC close/idle/reset;
  the macOS service logs `VPN transport stopped reason=… transport=… uptime_ms=…` and
  `VPN reconnect failed: stage=… reason=…`. GOAWAY debug data and QUIC reason
  phrases are not kept.
- **macOS managed access freshness** (#115): the helper advertises
  `managed_access_freshness` only with service-owned lease enforcement; one
  sticky deadline on the sleep-inclusive clock covers preparation, guard,
  dataplane and reconnect; expiry drains the tunnel and keeps the guard until
  Stop or Recover. The client still refuses helpers without it.
- **Windows guard probe** (#116, issue #81 stays open): a silent `sendto` counts
  as blocked only with a matching WFP `CLASSIFY_DROP` net event from our own
  provider and sublayer (read-only `FwpmNetEventEnum0`, at most 0.5 s per
  round); otherwise `unknown`. Each run journals
  `system_probe guard=… audit=… attempts=… dns=…` with enum names only.
