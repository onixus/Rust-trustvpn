# R-TrustTunnel 0.6.2

[Русский](#русский) · [English](#english) · [Технические детали / Technical details](#technical-details)

## Русский

### Коротко

0.6.2 — релиз про надёжность. VPN теперь лучше переживает сон компьютера и
телефона, сам замечает, что соединение «зависло», и честнее показывает,
защищён ли ваш трафик на самом деле.

### Что стало лучше

**После сна VPN снова работает сам.** Раньше после пробуждения Mac значок
показывал «подключено», а сайты не открывались, пока вы вручную не нажимали
«Отключить» и «Подключить». Теперь соединение восстанавливается само.
На Android после сна телефон тоже переподключается сам и не тратит попытки
впустую.

**Зависшее соединение больше не прячется.** Бывает, что пара соединений ещё
работает, а все остальные сайты молча не грузятся. Теперь приложение это
замечает и переподключается. В режиме прокси (SOCKS) оно тоже переподключается
само, и при этом трафик не уходит мимо VPN.

**Видно, работает ли защита.** В режиме «весь компьютер» строки
«Защита» и «DNS» становятся зелёными, только когда приложение действительно
проверило, что трафик не утекает мимо VPN. Если защита сломана — вы увидите
«ошибка», а не ложный зелёный значок. Проверки запускаются, только пока окно
приложения открыто, поэтому в фоне не тратят ресурсы.

**Быстрее отключение.** На Mac кнопка «Отключить» срабатывает меньше чем за
полсекунды, а окно не подвисает, пока VPN останавливается.

**Уживается с другими VPN.** Если до этого был запущен Cisco AnyConnect или
похожий клиент, R-TrustTunnel больше не отказывается подключаться.

**Смена Wi-Fi на Android.** Возвращение в Wi-Fi больше не обрывает открытые
загрузки и звонки без настоящей причины.

**Новый внешний вид** на всех платформах и терминальный клиент для Linux.

### Как обновиться

- **macOS:** закройте R-TrustTunnel, скачайте
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` и установите **один** из пакетов
  внутри: Native, WebView или Both. Если приложение открыто, установщик покажет
  непонятную ошибку скрипта — просто закройте приложение и повторите.
- **Android:** устанавливайте поверх 0.6.0, 0.6.1 или беты 0.6.2 — профили
  сохранятся. Версии 0.5.x и старше сначала удалите (при этом удалятся
  локальные профили — заранее экспортируйте их).
- **Windows / Linux:** окно приложения и служба VPN должны быть из одного
  релиза — обновляйте их вместе.

### Что пока стоит знать

- Пакеты для macOS не подписаны Apple Developer ID; при первом запуске
  может понадобиться разрешить запуск в «Системных настройках → Конфиденциальность
  и безопасность». Установщик Windows не подписан, SmartScreen может
  предупредить.
- Это всё ещё предварительная версия: не все сценарии проверены на
  установленных пакетах (см. таблицу ниже).

## English

### In short

0.6.2 is a reliability release. The VPN now survives sleep better, notices
on its own when the connection has stalled, and shows more honestly whether
your traffic is really protected.

### What got better

- **The VPN works again after sleep.** Previously, after a Mac woke up, the
  icon said "connected" but sites did not load until you pressed Disconnect and
  Connect. It now recovers by itself. Android also reconnects after sleep
  without wasting its retry attempts.
- **A stalled connection no longer hides.** When a couple of connections still
  work but everything else silently hangs, the app now notices and reconnects.
  Proxy (SOCKS) mode reconnects too, and traffic never goes around the VPN
  meanwhile.
- **You can see whether protection works.** In whole-computer mode the
  Protection and DNS rows turn green only after the app has actually checked that
  nothing leaks past the VPN. A broken guard shows "failed", not a false green.
  The checks run only while the app window is open.
- **Faster disconnect.** On a Mac, Disconnect takes under half a second, and the
  window stays responsive meanwhile.
- **Works alongside other VPNs.** After Cisco AnyConnect or a similar client,
  R-TrustTunnel no longer refuses to connect.
- **Wi-Fi changes on Android** no longer drop open downloads and calls without
  a real reason.
- **New look** on all platforms and a terminal client for Linux.

### How to update

- **macOS:** quit R-TrustTunnel, download
  `R-TrustTunnel-macOS-arm64-UI-Choices.dmg` and install **one** package from it:
  Native, WebView or Both. If the app is running, the installer shows an unclear
  script error; quit the app and try again.
- **Android:** install over 0.6.0, 0.6.1 or the 0.6.2 beta; profiles are kept.
  Uninstall 0.5.x and older first — this deletes local profiles, so export them.
- **Windows / Linux:** the app window and the VPN service must come from the
  same release; update them together.

### Good to know

- macOS packages are not signed with an Apple Developer ID, and the Windows
  installer is not Authenticode signed; your OS may ask you to confirm the launch.
- This is still a preview: not every scenario has been checked on installed
  packages (see below).

## Technical details

Workspace 0.6.2, desktop update **sequence 12**, Android versionName `0.6.2` /
versionCode 60202, iOS 0.6.2 (60202). Desktop control IPC **v7**: GUI and service
must come from the same package. Previous releases: [v0.6.2-beta.1](https://github.com/onixus/Rust-trustvpn/releases/tag/v0.6.2-beta.1)
(macOS and Android only, 60201) and [v0.6.1](v0.6.1.md).
macOS publishes only the UI Choices DMG ([release assets](README.md)).

### Since v0.6.2-beta.1
- **macOS wake reconnect** (#100, issue #99): free smoltcp sockets reset in
  SYN-RECEIVED and discard the utun backlog accumulated during sleep, so the
  reconnected data plane carries traffic instead of stalling for up to 300 s.
- **Quiet-flow liveness** (#103, #99): per-session ring of mature TCP flows on
  443/853/8443/80 that wrote and got no reply within 10 s; a few live flows (or
  the UDP relay/ICMP) no longer mask hundreds of stalled ones.
- **SOCKS degraded reconnect** (#104): native proxy mode stops the listener and
  retries the same profile and port under the shared recovery budget; clients
  get *refused*, never a direct path.
- **Probes only while viewed** (#102, #90): IPC v6 → v7, `Status` carries an
  optional `viewed`; system probes run only while a visible UI marks the session.
  Updater admission of v6 is unchanged, so Windows rollback still works.
- **macOS assets** (#98): one `R-TrustTunnel-macOS-arm64-UI-Choices.dmg`;
  `bundled-candidate` is no longer built.
- CI/test only: ICMP echo retries in tun-interop and cargo job limit (#101);
  Stop bounded on the real clock in two paused-time tests (#105, #106).

### In v0.6.2-beta.1 (since v0.6.1)
- macOS guard proof by a read-only BPF tap plus a per-run control frame (#96, #81).
- Desktop service probes of DNS and guard in whole-computer mode (#84, #91).
- macOS Stop/reconnect: Stop on its own supervisor, Status answers meanwhile,
  `stop_timing`/`reconnect_timing` in `events.log` (#80, #94).
- Foreign PF states (Cisco AnyConnect) flushed after our guard loads (#95).
- Android: sleep recovery (#92), IPv6 appearance after Wi-Fi no longer rebuilds
  the session (#86, #89), UI variant 3 (#73).
- All clients: dead-session detection (#69), UI v3 on Native/WebView/iOS (#74),
  Linux terminal client `rtrust-tui` (#72), lab acceptance (#87, #88).
