# Linux: весь компьютер

В native UI выберите «Весь компьютер · IPv4 + DNS», задайте IPv4 DNS-сервер и нажмите верхнюю кнопку подключения. Служба запускается для разрешённого desktop UID, но этот режим изменяет маршрутизацию **всего компьютера**, включая root и других пользователей. Выбранные CIDR сохраняются отдельно и используются только в режиме выбранных сетей. Автоматического подключения при загрузке профилей нет.

Требуются установленная `rtrust-service`, `iproute2`, `nftables`, активный `systemd-resolved` и профиль HTTP/2. В Debian/Ubuntu зависимости: `iproute2 nftables systemd-resolved`. Изменение системного DNS-менеджера установщик не выполняет. Если `resolvectl status` не работает, подключение отклоняется. Служба добавляет DNS и routing domain `~.` только своему TUN-интерфейсу; настройки чужих интерфейсов и `/etc/resolv.conf` не переписывает. Для системного разрешения через выбранный сервер должна использоваться интеграция systemd-resolved (stub resolver либо NSS resolve).

## Границы режима

- TCP и UDP IPv4 направляются через настоящий TUN и TrustTunnel HTTP/2. ICMP не реализован.
- IPv6-прикладной трафик блокируется; IPv6-туннелирования пока нет.
- Forwarded traffic, в том числе контейнеры/виртуальные машины за хостом, блокируется. Режим не предназначен для VPN-шлюза.
- Прямой доступ к LAN не является исключением. Loopback сохраняется. DHCP broadcast и минимальный IPv6 neighbor discovery разрешены для поддержания интерфейса.
- DNS upstream по умолчанию — `1.1.1.1`; можно задать частный DNS, доступный со стороны VPN-сервера. Существующие DNS-кэши не сбрасываются.
- Нет автоматического прямого fallback при недоступности VPN. При нормальном отключении или закрытии окна GUI обычная сеть восстанавливается после подтверждения Stop. При аварии GUI/IPC блокировка сохраняется; после повторного запуска нажмите «Сбросить блокировку после аварии».

## Защита и восстановление

Сначала создаётся root-only журнал `/run/rtrust/full.json`, затем атомарно устанавливается собственная nftables-таблица `inet rtrust_full`. Она разрешает исходящий трафик только через `rtrust0`, loopback, служебные socket marks и перечисленные network-control исключения. Чужие firewall-таблицы не изменяются. При аварии nftables продолжает блокировать обход туннеля, включая IPv6.

Endpoint-адреса разрешаются до изменения сети и фиксируются на время сессии. Только транспортные TCP-сокеты службы получают `SO_MARK=0x5254` до отправки SYN. Правило `10529` отправляет такие сокеты в main; правило `10530` направляет остальной IPv4 в таблицу `51830`. В ней есть TUN default route и постоянный unreachable fallback. При потере TUN служба повторяет подключение с задержкой 2–30 секунд и восстанавливает маршруты и DNS перед возвратом Connected.

Отключение сначала возвращает DNS и удаляет принадлежащие службе правила/маршруты, затем снимает firewall-защиту. Подтверждение Stop отправляется после очистки. При ошибке очистки блокировка сохраняется. После потери IPC, SIGKILL или перезапуска службы нужен явный «Сбросить блокировку после аварии» от разрешённого пользователя; новое подключение не снимает её автоматически. После перезагрузки ОС ephemeral nftables/rules и `/run` исчезают: это защита активной сессии, не boot-time always-on VPN.

## Проверка

`python3 scripts/full-tunnel-interop.py /path/to/trusttunnel_endpoint` запускается только в одноразовом root Docker-контейнере. Проверка использует network namespace, настоящие DBus/systemd-resolved, официальный endpoint 1.1.0, HTTP 512 KiB и DNS-сервер, фиксирующий source IP. Проверяются три UID, DNS через `getaddrinfo`, прямой IPv6 до подключения/после Stop, блокировка при потере endpoint, автоматическое переподключение, авария GUI, SIGKILL/restart, запрет нового lease до Recover и сохранность чужой nftables-таблицы. Это не заменяет проверку установленного приложения в KDE/systemd на отдельной desktop-машине.

Jenkins запускает этот сценарий вместе с прежними selected-networks и TCP/UDP/half-close E2E в стадии `Linux native + full tunnel E2E`. Linux GUI проверяется в headless Weston/Wayland с удалённым DISPLAY и без X11 backend; Windows/macOS проходят свои native unit/build/smoke/E2E.
