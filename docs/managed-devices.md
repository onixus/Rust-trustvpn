# Управляемые устройства: клиент и граница сервера

Статус клиентской задачи [#35](https://github.com/onixus/Rust-trustvpn/issues/35):
защищённая привязка и получение профилей реализованы; сквозной lifecycle
индивидуальных VPN credentials остаётся зависимым от серверной задачи
[onixus/tunnel#22](https://github.com/onixus/tunnel/issues/22).

## Привязка и секреты

Клиент принимает только HTTPS origin без пути, credentials, query или fragment.
HTTP redirect запрещён; сертификат проверяется. Одноразовый код отправляется
только этому origin. Его срок и повторное использование проверяет сервер внутри
транзакции enrollment: код непрозрачный, клиент не может достоверно извлечь его
срок или доказать, что он уже использован. QR-контракт пока не определён и QR
не считается поддержанным способом передачи.

Ответ существующего API `/portal/v2/enroll` содержит токен, `device_id` и
`expires_in`. Срок считается от начала запроса, чтобы сетевое ожидание не
продлевало доступ; нулевой или переполняющий срок отклоняется. По истечении
известного срока токен не отправляется даже при недоступной панели. Старый
сервер или прежняя привязка без срока дают неизвестный срок, а не бессрочный
доступ. Старые поля `{origin,token}` читаются; новые необязательные поля
потребуют повторной привязки при возврате к старому клиенту.

Токен хранится только в системном keyring и проверяется повторно при чтении.
VPN credentials и исходные версии профилей хранятся в encrypted vault.
Диагностика клиента не печатает токен, код или скачанную конфигурацию.
Код и токен не передаются как аргументы запуска интеграционной проверки.

## Партия синхронизации и offline

`Client::snapshot()` проверяет capabilities существующего API v2, получает
полную партию профилей с проверкой каждой ревизии на export и политику группы,
затем повторно проверяет список профилей и политику. Изменение ревизии, состава,
источника, маршрутов, неподдерживаемая capability или ошибка любого запроса
отклоняют всю партию. Лимиты: 200 профилей, 4 MiB сериализованных профилей;
настольный клиент дополнительно ограничивает получение 30 секундами.
Новый API версии 3 не интерпретируется как совместимый v2.

Сервер v2 не выдаёт общую транзакционную ревизию профилей и политики.
Повторная проверка обнаруживает наблюдаемые изменения, но не доказывает
существование единого server snapshot и не обнаруживает изменение туда и обратно
между запросами. Для строгой серверной атомарности нужен новый контракт.
Локальная партия применяется вместе; конфликт локальной версии откладывает
профили и маршруты до решения пользователя. Независимые локальные профили
не удаляются при ошибке или отсутствии профиля в выдаче сервера.

При timeout, offline, отказе API или устаревших данных последняя локальная
конфигурация сохраняется. Она может по-прежнему открыть VPN-соединение:
клиент не объявляет её доступ подтверждённым или актуальным. Срок API-токена
не равен сроку VPN credentials. Ответ 401 означает «токен истёк или API-доступ
отозван»; он не позволяет отличить причины и не доказывает отзыв на endpoint.
Протокол v2 не определяет максимальную свежесть offline-policy, renewal,
credential rotation или серверную обязательную остановку локального туннеля.

## Источник и ownership

`portal_managed` означает профиль, подготовленный панелью; `external_stored`
означает внешний профиль, сохранённый на панели. Ни одна метка не доказывает
уникальные credentials устройства или поддержку endpoint revocation.
Неизвестный origin сохраняется как неизвестный источник; локальный импорт
остаётся независимым unmanaged-профилем. Ответ v2 не содержит admin/user/local
ownership, обязательности профильной политики или разрешения на failover.
Эти свойства нельзя выводить из имени профиля, префикса `managed-` или группы.
Маршруты группы v2 применяются к настольному TUN; наличие профиля не даёт
разрешения обходить их через резервное подключение.

## Матрица совместимости

| Возможность | Windows/Linux/macOS native | Android/iOS | Сервер v2 |
| --- | --- | --- | --- |
| HTTPS enrollment, keyring, bounded sync | реализовано | общая Rust API; интеграция UI не подтверждена | one_time_code, profile_json |
| Group IPv4 routes | TUN, include/exclude/LAN | применение device policy не подтверждено | routing v1 или legacy 404 |
| Profile-embedded policy + group reconciliation | контракт отсутствует | контракт отсутствует | отсутствует |
| Device-specific VPN rotation | не подтверждено | не подтверждено | зависит от tunnel#22 |
| Endpoint revoke + active-session SLA | не подтверждено | не подтверждено | зависит от tunnel#22 |
| QR, renewal, freshness deadline | контракт отсутствует | контракт отсутствует | контракт отсутствует |

«Забыть локально» удаляет привязку keyring. Серверное удаление устройства
отзывает API tokens/grants/routing membership; уже скачанный VPN-пароль
существующая реализация не делает недействительным. Приёмка endpoint revocation
требует реальной новой попытки VPN-соединения со старыми credentials при
заблокированном portal API, а также отдельно определённой политики активных
сессий. До такой серверной реализации issue #35 нельзя считать полностью
закрытым.

Клиент автоматически не отправляет telemetry о посещённых адресах или трафике.
Обновление состояния/версии политики по согласию не реализовано: согласованного
минимального telemetry-контракта пока нет.

Android/iOS перед возвратом скачанной партии повторно читают `/portal/v2/profiles`.
Сравнение `id` → `(revision, origin)` не зависит от порядка списка. Изменение
ревизии, состава или источника отклоняет всю партию до атомарной записи vault;
дубликаты ID и некорректные ревизии отклоняются также в первом списке. Отсутствие
или JSON null в необязательном `origin` означает неизвестный источник; произвольная
валидная метка сохраняется при сравнении без выдумывания ownership. Валидная метка —
1–80 печатных ASCII символов (0x20–0x7E) одинаково на Android и iOS; сравнение
побайтовое. Иная метка отклоняет всю партию. Остановка WorkManager (`isStopped`)
и отмена Task прерывают партию до записи. Эта повторная
проверка обнаруживает наблюдаемые изменения, но не заменяет серверную транзакцию
и не обнаруживает изменение туда и обратно между запросами. Device acceptance
и endpoint revocation остаются отдельными gates.

Безопасный Android regression runner: `python3 scripts/test-android-portal-sync.py`
с существующими JDK (`JAVA_HOME`) и `org.json` JAR (`RTRUST_JSON_JAR`; на Debian
пакет `libandroid-json-java`). Он выполняет production download/fence на JVM
с синтетическими transport/parser; JNI, Android vault и реальные API не вызываются.
GitHub Linux gate запускает этот runner; iOS XCTest сценарии требуют отдельного
Xcode test gate и не считаются выполненными по одному typecheck.
