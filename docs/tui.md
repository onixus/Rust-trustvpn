# Консольный клиент `rtrust-tui`

Терминальный интерфейс для Linux-машин без графической сессии или для тех,
кому удобнее консоль. Это ещё один фронтенд поверх общего
`rtrust_desktop::Controller` — того же, что у WebView: импорт, хранилище,
выбор профиля, режимы и остановка сессии работают так же, как в GUI.
Отдельной сетевой логики у клиента нет.

```bash
cargo build --release -p rtrust-tui --locked
./target/release/rtrust-tui
```

## Возможности

- Список профилей; `★` — профиль по умолчанию, `●` — подключённый.
- Импорт ссылки `tt://` / `hy2://`, вставленного текста профиля или файла
  (`i`, поддерживается вставка из буфера). Перед сохранением показывается
  имя, сервер и протокол; без подтверждения профиль не сохраняется, а
  отклонённый предпросмотр удаляется из памяти.
- Подключение выбранного профиля (`Enter`), отключение (`d`).
- Режимы (`m`): SOCKS5/HTTP-прокси, TUN для выбранных IPv4-сетей, весь
  компьютер. Сети (`n`), исключения (`e`), локальная сеть (`l`), порт прокси
  (`p`), DNS (`o`), автоподключение (`a`).
- Состояние сессии: наблюдения службы (транспорт, маршрут, DNS, защита,
  доступность), трафик прокси, резервный профиль, сбой проверки жизненного
  цикла.
- Снятие оставшейся блокировки после сбоя другого клиента (`R`).
- Файл профиля можно передать аргументом: `rtrust-tui ~/profile.toml` —
  откроется подтверждение импорта. Ссылку с учётными данными в аргументах
  не передавайте: она попадёт в историю shell и в `/proc/<pid>/cmdline`,
  видимый другим пользователям. Вставляйте её через `i`.
- В поле импорта открытым текстом показывается только явный путь
  (`/`, `~/`, `./`, `../`); ссылки, JSON и вставленные конфиги маскируются.
- Язык выбирается по `LC_ALL` / `LC_MESSAGES` / `LANG` (`ru*` — русский).

## Требования

- **Хранилище ключей.** Профили шифруются, ключ хранится только в Secret
  Service пользовательской D-Bus-сессии (GNOME Keyring, KWallet, KeePassXC).
  Plaintext-режима нет. На сервере без desktop-сессии нужен запущенный и
  разблокированный keyring, например:

  ```bash
  dbus-run-session -- sh -c 'stty -echo; read -r P; stty echo
    printf %s "$P" | gnome-keyring-daemon --unlock --components=secrets >/dev/null
    unset P; exec rtrust-tui'
  ```

  Пароль связки вводится вслепую и передаётся демону через stdin, не через
  аргументы. Связка, созданная так впервые, получает этот пароль. Без
  разблокированного хранилища клиент завершается с ошибкой до открытия
  интерфейса.
- **TUN и «весь компьютер»** требуют установленной системной службы
  R-TrustTunnel ([linux-service.md](linux-service.md)); клиент только
  управляет ею через аутентифицированный IPC.
- **SOCKS5/HTTP** работает внутри процесса `rtrust-tui`: прокси живёт, пока
  открыт клиент.

## Завершение и сигналы

- `q`, `Esc` или `Ctrl+C` при активной сессии спрашивают подтверждение и
  отключают VPN перед выходом. Если отключение не удалось, клиент остаётся
  открытым и показывает ошибку.
- Без терминала (stdin не TTY) клиент сразу завершается с ошибкой.
- `SIGTERM`, `SIGHUP` (закрытый терминал, обрыв SSH) и потеря терминала
  отключают VPN и завершают процесс. Если запущено другое действие,
  например подключение, выход выполняется после него. Если служба не
  ответила на остановку, процесс всё равно завершится с ошибкой, а её
  защита остаётся в fail-closed-состоянии до `R` или перезапуска службы.

## Ограничения

- Портал (регистрация, синхронизация, загрузка профилей), экспорт профиля и
  системная диагностика пока доступны только в GUI.
- Проверено: unit-тесты состояния и рендера (`cargo test -p rtrust-tui`),
  отсутствие учётных данных на экране для синтетического профиля. Сетевое
  поведение наследуется от общего контроллера и проверяется его тестами и
  Linux E2E; отдельная приёмка `rtrust-tui` на установленной машине не
  проводилась.
