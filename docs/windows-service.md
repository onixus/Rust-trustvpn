# Windows Wintun-служба

Native GUI использует собственный Rust HTTP/2 transport и Wintun, без запуска официального CLI. Служба `RTrustTunnel` работает через Windows SCM от LocalSystem; GUI запускается обычным пользователем. Доступны выбранные IPv4-сети и полный IPv4-туннель **всего компьютера** через HTTP/2.

## Установка

Запустите `R-TrustTunnel-Windows-x64-Setup.exe` (Windows 10 2004+ x64). Мастер установит приложение, службу и ярлыки. Укажите обычную учётную запись `COMPUTER\user`, которая будет управлять VPN. Отдельный Visual C++ Redistributable не требуется. Setup пока не подписан. Повторный запуск обновляет приложение; удаление доступно в Windows Settings → Apps.

Для ручной установки в ZIP-артефакте Jenkins находятся `R-TrustTunnel.exe`, `rtrust-service.exe`, официальный подписанный `wintun.dll`, его лицензия и `install-windows-service.ps1`. Откройте PowerShell от администратора в каталоге пакета:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-windows-service.ps1
```

`ExecutionPolicy Bypass` действует только для этого процесса PowerShell и не меняет системную политику.

Если повышение выполнено под другой учётной записью, передайте `-AllowedSid S-1-5-21-...` пользователя, который будет запускать GUI. Его SID можно получить командой `whoami /user` в обычной пользовательской сессии. Не запускайте GUI постоянно от администратора.

В GUI выберите «TUN · выбранные IPv4-сети», укажите необходимые CIDR и подключите профиль верхней кнопкой (для TUN клиент выбирает HTTP/2). Режим и сети сохраняются вместе с профилями автоматически. Импорт не меняет маршруты и не запускает VPN.

Удаление из повышенного PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-windows-service.ps1 -Action Remove
```

Установщик проверяет Authenticode Wintun, защищает каталог `Program Files\RTrustTunnel Service` от записи обычными пользователями, регистрирует автоматический запуск службы. После запуска ОС служба ожидает команды GUI и сама VPN не подключает. Обновление выполняется повторным запуском установщика; действующая сессия при обновлении отключается. Setup.exe использует тот же скрипт для установки/обновления/удаления службы. Добавлены компоненты Native/WebView/Both; проверка нового установщика на Windows отложена до включения ноды. WebView требует установленный WebView2 Runtime; Native — нет.

## Полный туннель

Выберите «TUN · весь компьютер», задайте IPv4 DNS-сервер, доступный через VPN, и подключите профиль: GUI выберет HTTP/2, служба закрепит IPv4-адреса endpoint. DNS назначается только Wintun; настройки физического Ethernet/Wi-Fi не меняются. IPv6, прямые LAN-соединения и forwarding блокируются. Loopback и DHCP остаются доступны.

Постоянные WFP-фильтры разрешают выход к endpoint только исполняемому файлу службы по TCP на порт профиля. При аварии GUI или службы защита остаётся. SCM автоматически перезапускает упавшую службу, чтобы сброс через обычный GUI снова стал доступен. Для возврата обычной сети нажмите «Сбросить защиту»; восстановление удаляет только собственные маршруты/фильтры и ждёт удаления Wintun-адаптера. После сброса подключение возможно сразу. Stop штатно снимает защиту; запуск Windows/GUI сам VPN не подключает.

Если GUI недоступен, администратор может остановить службу и выполнить `"C:\Program Files\RTrustTunnel Service\rtrust-service.exe" --recover`, затем запустить службу. При ошибке восстановления журнал и защита сохраняются.

## Контракт и ограничения

- Один настроенный desktop SID и одна активная сессия. Pipe ACL разрешает только SYSTEM и этому SID; право создавать экземпляры pipe пользователю не выдаётся, удалённые pipe-клиенты запрещены.
- GUI сверяет PID pipe-сервера с зарегистрированной LocalSystem-службой SCM до отправки профиля. Это работает без чтения защищённого токена SYSTEM из обычной пользовательской сессии.
- IPC версионирован, кадры ограничены по размеру, первоначальное чтение и подключение имеют тайм-ауты. Профиль не записывается службой на диск.
- Разрешены 1–16 непересекающихся IPv4 CIDR /8–/32. Конфликты с существующими маршрутами и адаптером отклоняются. DNS-ответы адреса endpoint фиксируются на время сессии; пересечение endpoint с выбранными сетями запрещено.
- Маршруты создаются через IP Helper API, удаляются только добавленные службой записи. Используется адрес Wintun `169.254.254.2/32`; существующие интерфейсы и VPN не перенастраиваются.
- При потере endpoint Wintun и его маршруты удерживаются, транспорт переподключается с задержками 2–30 секунд. Старые TCP-соединения не переносятся. Stop/закрытие GUI отменяет транспорт и удаляет маршруты. SCM Stop выполняет ту же очистку.
- Режим выбранных сетей не защищает весь трафик: в нём DNS/IPv6 остаются системными, постоянный WFP kill switch включается только в полном режиме. IPv6 transport, ICMP и фрагментация пока не поддерживаются.

Wintun 0.14.1 берётся с [официального сайта](https://www.wintun.net/); SHA-256 архива закреплён в `ci/wintun.py`. Загрузка идёт в CI, а не из привилегированного работающего сервиса. DLL загружается по абсолютному пути рядом с защищённым исполняемым файлом.

## Проверка

`ci/windows_service_e2e.py` отказывается заменять установленную пользователем службу. На административной Windows-ноде он временно устанавливает службу, проверяет IPC и сетевой путь через отдельный официальный endpoint в Docker, затем удаляет службу и сравнивает всю IPv4-таблицу маршрутов с исходной. Тест использует синтетические credentials и только `10.231.243.2/32`; production endpoint не затрагивается. При конфликте тестовой сети тест прекращается, не отключая существующий VPN.

Проверяются: версия IPC, недопустимые маршруты, неправильный пароль, эксклюзивная сессия, 8 параллельных HTTP-загрузок по 512 KiB, UDP 1/512/1472, обрыв и восстановление endpoint, Stop ACK, тот же Rust IPC client, который использует GUI, закрытие процесса клиента и SCM Stop. Тесты native GUI отдельно проверяют запуск окна, а не автоматические нажатия всех кнопок. Первый полный прогон: [Jenkins #12 — SUCCESS](http://localhost:8081/job/rtrust-native/12/). История исправлений и последующие результаты: [Jenkins](jenkins.md).

Историческая сборка выбранных сетей: [Jenkins #13 — SUCCESS](http://localhost:8081/job/rtrust-native/13/), [ZIP с приложением и службой](http://localhost:8081/job/rtrust-native/13/artifact/dist/R-TrustTunnel-Windows-preview.zip).

`ci/windows_full_runner.py` запускает full-tunnel E2E отдельной защищённой SYSTEM-задачей с независимым таймером восстановления сети. Проверяются TCP/UDP, системный DNS, блокировка ранее открытых соединений, перезапуск endpoint, аварии GUI/службы, сохранение защиты после перезапуска службы и восстановление исходных маршрутов. `ci/windows_installer_e2e.py` проверяет настоящий Setup: install, upgrade, GUI smoke, WFP canary и uninstall. Эти тесты требуют отдельного разрешения на изменение сети CI-машины; для текущей Windows-ноды оно дано пользователем.
