# Команда агентов R-TrustTunnel

Коллекция предназначена для выполнения issue в этом репозитории. Координатор —
главный агент текущего чата; шесть специалистов задаются файлами
`.codex/agents/*.toml`. Модель и уровень рассуждений наследуются от родителя.
Настройки не меняют глобальную конфигурацию, подключения или политику одобрений.

| Агент | Задача | Результат | Режим по умолчанию |
| --- | --- | --- | --- |
| architect | Границы, контракты, lifecycle, совместимость | План, инварианты, критерии приёмки | Чтение |
| devsecops | Секреты, доверие, привилегии, зависимости, CI и поставка | Риски и обязательные security gates | Чтение |
| network_engineer | DNS, маршруты, transport, firewall, recovery | Матрица сетевых сценариев и доказательств | Чтение |
| developer | Реализация и исправления | Scoped patch, тесты и объяснение изменений | Запись в workspace |
| tester | Воспроизведение, негативные сценарии, регрессии | Отчёт проверок для конкретного SHA | Запись в workspace |
| reviewer | Независимая оценка конфиденциальности и стабильности | Замечания и решение о готовности | Чтение |

Ограничение проекта — три дочерних агента одновременно; главный агент занимает
четвёртый слот. Доступность и фактические лимиты среды имеют приоритет.
Read-only режимы — настройки по умолчанию; текущая политика среды может их
переопределить. Запрет редактирования для аналитиков также задан инструкциями.
Ограничения connector/API действий проверяются отдельно от файлового sandbox.

## Порядок выполнения

1. Координатор читает issue, зависимости, связанные PR, текущий head и dirty
   state. Формирует область задачи и список критериев с владельцами.
2. Архитектор, DevSecOps и сетевик независимо исследуют затронутые пути.
   Координатор разрешает противоречия и передаёт разработчику единый план.
3. Разработчик реализует scoped patch и проверки. У файлов один владелец;
   общий checkout не используется для конкурирующих изменений.
4. После фиксации кандидата тестировщик проверяет поведение, ревьювер — diff,
   DevSecOps или сетевик — соответствующие риски. Тестировщик может добавлять
   согласованные тесты; тогда получается новый кандидат и новый SHA для ревью.
   Привилегированные сетевые тесты запускаются в изолированной лаборатории,
   не меняют рабочий VPN или firewall пользователя без разрешения.
5. Разработчик исправляет замечания. Координатор собирает доказательства для
   финального SHA и проверяет актуальность обязательных CI gates.
6. Результат передаётся как готовый PR или локальный patch согласно поручению.
   Merge — по прямому разрешению. Issue закрывается только после выполнения
   всех его критериев; внешние зависимости и device acceptance остаются видимыми.

## Приёмка конфиденциальности и стабильности

- В логах, диагностике, экспортируемых отчётах и ошибках нет секретов или
  ненужных идентификаторов. Экспорт credentials остаётся явным действием.
- Stored profiles не имеют plaintext fallback; TLS и signed updates не ослаблены.
- DNS/IPv4/IPv6, split/full tunnel, bypass и failover проверены в затронутой
  области; отсутствие утечек заявляется только по наблюдаемым доказательствам.
- Проверены необходимые отказные сценарии: timeout, потеря сети, отмена,
  параллельные Connect/Disconnect, смена профиля, устаревший async result,
  sleep/wake и crash recovery. Чужое состояние ОС сохраняется.
- Для каждого критерия записаны SHA, платформа, вид проверки, результат и
  ограничения. Нельзя подменять native/device acceptance результатом mock/CI.
- Подтверждённые блокирующие замечания устранены; NOT RUN и BLOCKED не
  превращаются в PASS. Набор тестов определяется реальными путями и текущим CI.

## Примеры поручений

Полный цикл:

> Возьми issue #N в работу командой из architect, devsecops, network_engineer,
> developer, tester и reviewer. Доведи до PR и CI, с приоритетом
> конфиденциальности и стабильности. Merge после моего разрешения.

Локальная реализация:

> Исправь issue #N этой командой локально, без публикации. Покажи результаты
> тестов и независимого ревью для итогового изменения.

Ревью:

> Проверь PR #N агентами reviewer, devsecops и network_engineer для текущего
> head. Верни подтверждённые дефекты, непроверенные риски и обязательные gates.

Формат standalone TOML и наследование настроек сверены с
[официальной документацией OpenAI](https://learn.chatgpt.com/docs/agent-configuration/subagents).
При следующем запуске в проекте проверь, что среда обнаружила шесть ролей.
Если именованные роли недоступны в текущем интерфейсе, координатор передаёт
субагентам текст `developer_instructions` из файлов, сохраняя те же обязанности.
