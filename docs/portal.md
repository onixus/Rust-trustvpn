# Обмен профилями с сервером

`vpn.example.com` — условный адрес; замените его доменом вашей панели.

## Windows, Linux и macOS

1. Откройте https://vpn.example.com/profiles и войдите в существующую учётную запись.
2. Создайте одноразовый код привязки устройства.
3. В приложении откройте «Серверная панель». Укажите `https://vpn.example.com`, имя устройства и код, затем привяжите устройство.
4. В браузере выдайте этому устройству доступ к нужным профилям. В приложении обновите список.
5. Загрузка открывает предварительный просмотр импорта. Добавьте профиль: локальное хранилище сохранится автоматически. Подключение VPN выполняется отдельно.

Чтобы отправить локальный профиль на сервер, выберите его, разрешите передачу
VPN-пароля и запросите предварительный просмотр. Проверьте результат и отдельно
подтвердите создание серверной копии. Это сохраняет конфигурацию, но не создаёт
нового VPN-пользователя на endpoint.

Привязка хранится в системном хранилище секретов. После перезапуска приложения
воспользуйтесь восстановлением сохранённой привязки. Если системное хранилище
недоступно, приложение сообщает ошибку и не сохраняет токен открытым текстом.
Код одноразовый: после неудачного сохранения привязки получите новый код, а
неиспользуемое устройство удалите в браузере.

«Забыть» удаляет локальную привязку. Для отзыва API-доступа удалите устройство
на серверной странице. Это не отзывает уже скачанные VPN-пароли — их нужно
сменить средствами управления VPN. Передавайте конфиги только доверенному
серверу: они содержат данные подключения.

## Синхронизация и конфликты на настольных клиентах

После привязки можно отдельно включить автоматическое получение изменений.
Клиент раз в минуту проверяет выданные устройству профили, пока VPN отключён
и нет несохранённых изменений. Одна проверка ограничена 30 секундами и 4 MiB
скачанных профилей. Привязка восстанавливается из системного keyring; источник
должен совпадать с сохранённым HTTPS origin. Изменения применяются только после
успешного получения всей партии. Превышение лимитов не меняет локальные данные.

Неизменённые локально профили обновляются на месте. Если профиль изменён или
удалён локально, можно оставить локальную версию либо добавить серверную отдельной
копией. Недоступный на сервере профиль не удаляется локально автоматически.
Это синхронизация получения; автоматической отправки локальных паролей нет.
Настройка, ревизии и исходные версии хранятся в зашифрованном vault.

После предварительного просмотра отправки можно создать серверную копию либо
явно заменить один из внешних серверных профилей. Замена проверяет ревизию;
при конфликте обновите список и повторите просмотр. Управляемые сервером
VPN-учётные записи этим API не заменяются.

## Маршруты TUN для групп устройств

На странице `/profiles` в разделе «Маршруты TUN для групп устройств» можно
создать до 50 групп. Для группы задаются сети IPv4, которые идут через VPN
(1–16 сетей CIDR, допускается `0.0.0.0/0`), исключения (до 64 сетей) и флаг
«Исключить локальные сети». Сети проверяются строго: `10.0.0.1/8` отклоняется,
нужно `10.0.0.0/8`. Привязанное устройство добавляется в группу кнопкой
«Добавить в группу»; устройство состоит не более чем в одной группе, добавление
в другую группу переносит его. Отзыв устройства или удаление группы снимает
политику.

Настольный клиент получает политику своей группы запросом
`GET /portal/v2/routing` с токеном устройства и применяет её в режиме TUN при
следующем подключении. Ответ `{"policy":null}` означает, что группы нет; ревизия
`"<id группы>:<версия>"` меняется при каждом изменении группы или переносе
устройства. Сервер без этой функции отвечает 404 — клиент считает, что политики
нет. Браузерная сессия не может вызвать `/routing`, а токен устройства — менять
группы. Правки сохраняются с проверкой ревизии: при конфликте обновите
страницу.

Настройка и развёртывание серверного редактора относятся к отдельному проекту
[onixus/tunnel](https://github.com/onixus/tunnel). Этот репозиторий содержит клиентскую
часть получения политики маршрутов.

## Android

Android preview использует тот же реализованный API v2, но синхронизирует профили
**вручную**. Фоновый опрос и разрешение конфликтов настольного клиента на Android
пока не перенесены.

1. В серверном UI `/profiles` создайте одноразовый код (срок действия — 180 секунд).
2. На телефоне откройте «Профили сервера». Укажите HTTPS origin панели, код и имя устройства. Origin не должен содержать путь, query, fragment или логин/пароль. Перенаправления не принимаются.
3. В серверном UI выдайте зарегистрированному устройству доступ к профилям.
4. Отключите VPN и выберите «Загрузить / синхронизировать», затем подтвердите загрузку учётных данных. При Always-on сначала измените системную настройку VPN.
5. Для загрузки в панель выберите «Отправить профиль» и подтвердите передачу учётных данных. Создаётся новая внешняя копия; VPN-пользователь и его пароль на endpoint не меняются. Замена существующего серверного профиля из Android UI пока не поддерживается.

Токен устройства (срок действия — 30 дней) сохраняется в зашифрованном vault с
ключом Android Keystore. Восстановление регистрации после перезапуска происходит
автоматически. Продления токена нет: после истечения или отзыва удалите локальную
регистрацию и получите новый одноразовый код.

Синхронизация получает все доступные устройству профили с проверкой ревизий и
применяет результат целиком. Предыдущие серверные копии обновляются, профили с
отозванными правами удаляются; локально импортированные профили сохраняются.
Существующий default сохраняется, если он всё ещё доступен; иначе выбирается
первый оставшийся профиль. При ошибке сети, авторизации или ревизии локальные
данные не меняются. Общий лимит локального списка — 64 профиля.

«Удалить регистрацию» удаляет токен и скачанные серверные копии с телефона;
локальные импортированные профили остаются. Отдельно отзовите устройство в панели.
Отзыв API-токена не аннулирует уже выданный VPN-пароль — при необходимости смените
его средствами управления endpoint. Автоматической отправки секретов нет.

На физическом Android 12 проверены регистрация, загрузка, отправка синтетического
профиля, отзыв права с удалением локальной серверной копии и восстановление права
с повторной загрузкой. Локальный профиль по умолчанию сохранился. Тестовая
серверная копия отозвана; её payload удалён.
